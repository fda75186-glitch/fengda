# 社区加载性能优化

基线是已确认恢复注册的公网0.1.9连接修复（edd77d674dbe4a094d0156081c5e47be4445c657）。本版只包含加载优化，不包含待确认的0.1.10知识卡自动配图界面。用户已于2026-10-16确认性能预览并授权上线。

## 用户可感知的变化

- 登录成功立即返回，帖子在后台刷新，不再让登录窗口等待帖子和全部私密附件。
- 被动进入社区或打开已加载帖子可复用同账号5秒内的列表；手动重试和发布、点赞、评论后仍强制刷新。
- 列表包含事务快照版本，SSE只在版本变化时刷新；读取过程中收到新版本会补读。附件失败也不会吞掉补读，接口失败则不循环重试。
- 相同私密附件合并进行中的下载，换账号时中止旧请求；缓存按会话隔离。视频依然需要实际下载，未宣称传输本身提速。
- 首页按需加载地图等其他页面。AI首次进入才挂载，之后保留对话；AI和分享基础代码保持静态可用，分享窗口沿用原有常驻挂载和关闭动画。

## 测量与限制

固定接口40ms、媒体120ms的隔离对照，三次中位数：普通登录115→44ms，含私密视频登录223→45ms。相同操作序列的完整列表请求7→2次；12个相同图片引用的下载12→1次。上述为固定延迟实验，不是大陆公网延迟或实际浏览器测量。

同一生产构建方式中，首屏JS+CSS gzip约227,988→143,493字节，减少约37%；新增160KiB初始资源预算检查。Three.js和地图JS原本已经动态加载，未将它们误算为首页阻塞资源。12.83MB首页视频未改内容或画质。

5000篇帖子、10万点赞和10万评论的内存SQLite夹具中，列表及评论查询中位数33.354→12.168ms。登录数据库调用7→5次；列表匿名2次、已登录3次保持不变。当前公网抽测仅有2篇公开帖子、响应约2.7KB，因此没有将大数据夹具的改善宣称为当前公网提速幅度；原线路还存在较明显网络往返波动。

查询先按已有索引选取200个轻量ID，再关联正文；评论复用已授权ID，通过json_each单参数保持D1参数上限。事务批次先读事件版本再读列表，避免订阅漏更新。不截断现有正文或评论，不降低密码哈希强度，不改变账号/媒体绑定，不新增迁移或付费基础设施。

初版候选把分享也改为首次异步挂载，虽然压缩资源可降至125,162字节，但首次打开分享无法触发原有弹窗初始化，复核后撤回该部分；AI保留静态代码以避免首次下载失败后保留空实例。最终采用较小但正确的37%减幅，旧版仍超过新的160KiB预算。

本机Miniflare在20秒内未完成D1初始化，没有执行兼容性SQL。SQLite测试、隐私/并发限流和构建通过。获批部署后，真实D1列表查询返回200及数字版本，匿名无效登录返回预期401，已实际验证batch读取、json_each与RETURNING路径；原公开帖子保留。未创建公网测试账号或帖子。

遵循项目约定，未进行自动UI、浏览器、GL或实际GPU审核，实际操作由用户人工预览。
